## Памятка проверяющему

#### Работа с дедлайнами

Для задания предусмотрено два дедлайна.

* Первый дедлайн - ~2 недели после выдачи. От студента требуется оформить полностью готовое решение. Если задание к первому дедлайну не готово, за задачу ставится 0 баллов.

* Второй дедлайн - ~4 недели после выдачи. Студент проходит этап ревью с проверяющими, исправляет замечания. Баллы выставляются по состоянию кода на момент второго дедлайна.


#### Что проверять

* Соответствие решения требованиям: решение делает то, что должно делать и не делает того, чего не должно делать.
* Покрытие unit-тестами. Покрытие должно быть достаточным и не избыточным.
* Прохождение автоматических тестов.
* Ошибки детектированы и обработаны: некорректный ввод пользователя / нехватка памяти / недоступность файла...
* Переусложнённые решения. Зачастую, для достижения цели достаточно более простых и понятных подходов.
* Понятность, читаемость кода.
* Соответствие cpp core guidelines.
* Не стоит требовать того, чего ещё не проходили в курсе.
* По наличию собственных ресурсов - дискуссия со студентом ("а что, если", "а как ещё можно")

В каждом замечании явно помечать, требуется ли ответная реакция или или это пометка в стиле "обратите внимание, бывает и такое". Например:

* Функционал F не покрыт юнит-тестами. Пожалуйста, добавьте.
* Класс C содержит ошибку в операторе перемещающего присваивания - утекает старый ресурс. Необходимо скорректировать.
* Есть и такой способ разбить строку пробелами: "...". Править не нужно.
* Класс C нарушает Single Responsiblity Principle, а именно ... . Как это можно исправить? Код править не нужно, только напишите предложение.


#### Использование ИИ

Прогнать хорошую ИИ-шку, собрать с неё возможные предложения по замечаниям - рабочий вариант.

* Рекомендовал бы им пользоваться во-первых, для самопроверки, во-вторых, для обогащения своего ревью. ИИ-шка может подсветить неожиданные ошибки. Раздел "Что проверять" можно загнать в промпт.
* Крайне не рекомендовал бы ограничиваться __только__ ИИ-ревью без человеческого проглядывания. И вслепую копировать замечания ИИ без их оценки проверяющим.


#### Штрафы и выставление баллов

Если студент сдал задачу, можно сразу выставить в ведомость полный балл.

Если есть огрехи - собраться проверяющим после каждой задачи и обсудить точные штрафы. Ориентировочно: мелкий недочёт - 0.25 баллов, ошибка в коде - 1 балл, непокрытый тестами функционал / половинчатое решение - штрафуется строже.
